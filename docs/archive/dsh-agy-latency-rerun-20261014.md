# DSH 与原生 AGY 编码链路重测（2026-10-14）

本次使用“工具配置按 AGY 会话加载一次”的修复版本，在隔离实例中重新执行真实编码任务。**DSH 耗时 851.714 秒（14 分 11.714 秒），原生 AGY 耗时 442.024 秒（7 分 22.024 秒），相差 409.691 秒，本次为 1.93 倍。** 两组均完成实现、测试和 README，实际执行单测，并通过独立的 18 项黑盒验收。生产实例未替换。

最明显的差异发生在 Windows DSH 的测试阶段：两次本地挂起各 120 秒，另有模型排障往返。配置重复已消除，本轮没有压缩或参数修复；网络、SSH、relay 和代理非 AGY 处理合计仅约 14.43 秒，不能解释 6 分 50 秒的差距。该差距还包含工具环境、模型决策和提示词的差异，不能称为纯代理减速倍数。

## 方法与边界

- 沿用前次 Python 标准库任务管理器任务，新增一条两组完全相同的要求：测试临时目录放在项目内。任务 SHA-256 为 `cb2ee43622925b2c104ad5ddff8b23803cfeb68e9ddc17ed1464edcda03576dd`；Windows 客户端与服务器任务文件逐字节一致。
- 两组分别使用全新空目录，没有复用上次生成的代码。DSH 仍使用源码安装、构建的 `deepseek-harness`，提交 `d743267388641bc76f17c45ce8b4c231aed1d32c`、版本 `0.2.1-alpha.2`，启动命令为 `pnpm dsh --profile headless --json -`，任务通过 stdin 传入，没有使用 npx。
- 上游都是同一托管账号、AGY **1.3.4**、`gemini-3.8-flash-high`、`effort=high`，两组顺序运行。DSH 客户端重试为 0，代理恢复预算为 1。
- DSH 工具运行在 Windows / Python **3.12.7** / `workspace-write`；原生 AGY 工具运行在 Linux 容器 / Python **3.12.15** / `accept-edits --dangerously-skip-permissions`。这仍是工作流对照，不是排除工具环境、提示词与随机性的纯代理开销实验。
- 本地透明 HTTP relay 经 SSH 本地端口转发访问容器内隔离代理。只增加测试关联头，原始请求体、工具定义和响应均不改写。服务器另记录会话启动、增量输入长度、CLI 事件、校验完成和 HTTP 交付时点，关联每条请求。
- 各侧耗时使用自己的单调时钟相减，不用两台机器的绝对时间差计算单程延迟。响应头、心跳与业务内容分别计量。
- 测试的应用源码 SHA-256 保存在证据中，与本地当前代码一致。独立测试数据目录不写生产请求记录，未修改生产流量或代理配置。

## 本次定位到的等待

### 本地单测两次等待 120 秒

任务开始后 377.156 秒，DSH 首次执行单测，等待 120.016 秒后转后台；随后重试又等待 120.011 秒。两个长等待都发生在客户端 shell 工具里，期间代理没有执行该任务的下一轮模型生成。

保存首次测试时的源码和测试快照，在同一 Windows / Python 3.12.7 下脱离 DSH 沙箱运行，**21 项单测用时 8.919 秒，全部通过**。这验证了当时生成的代码和测试能完成，不能把 120 秒解释成测试工作量本身。

DSH 自行诊断得到：`tempfile.mkdtemp` 创建目录成功，但 `scandir` 和 `rmdir` 报 WinError 5；同一沙箱内普通 `mkdir` 创建的目录能正常读写、删除。随后模型将测试临时目录换成普通工作区目录，实际在沙箱中完成 21 项单测。首次成功工具调用用时 8.825 秒，最后又重复验证一次，用时 15.388 秒。

首次执行单测到第一次成功结果约 **392.117 秒**，包含本地等待与模型多轮排障，不能全部算成网络或代理时间。固定到 Python 3.12、把临时目录放进项目，并未消除这个 Windows 沙箱目录权限问题。此次保留该问题的真实耗时，没有人工改写 DSH 生成的实现或测试。

### 模型进行了大量小步骤验证

DSH 主流程共 48 次模型请求。模型在落盘实现前，进行了多次 argparse 参数位置实验、原子替换和 Unicode 输出验证，后面又为沙箱故障增加多轮诊断。

最长 HTTP 请求为 **70.609 秒**，对应 AGY 执行为 **70.315 秒**，CLI 报告 reasoning 为 **8,422 tokens**；该轮最终请求执行 argparse 行为验证。另有 50.568、46.317、36.585 秒的请求，对应 AGY 分别为 50.160、46.108、36.359 秒。等待主要位于 AGY 执行阶段，不能用 HTTP 传输解释。

本轮全部主请求累计 output 为 58,327 tokens，其中 reasoning 32,001。两组都使用 high，不能仅凭这里的推理量认定 high 设置错误，或认定降低 effort 一定能保持相同任务质量。

### 配置重复修复确实生效

48 次主请求全部复用同一 AGY PID / conversation ID，**48 次生成尝试、0 次参数修复、0 次上下文压缩**。主会话 agent 配置只注册一份；所有实际用户输入的工具配置块均为 0。完整 DSH 工具定义继续由客户端提交，代理将固定契约放在会话配置中。

最大观察输入上下文为 **110,453 tokens**。前次未修复版本在 25 次主请求中达到 194,323 tokens，发生一次压缩和一次参数修复；本次请求更多，但未重现这种重复配置增长。

两次任务还存在模型决策、Python 版本、提示补充及本地故障时长差异，因此不能把总耗时变化全部归因于这一个修复，也不能声称修复后不再需要 AGY 原生压缩。先前单独的压缩兼容问题仍见[专项记录](session-tool-configuration-fix-20261013.md)。

## 准备阶段失败单独保留

1. 计时 relay 的任务完整性断言未统一 CRLF 换行，误判任务截断，主请求未转发。实际文本完整；修复测量脚本后重启，11.905 秒的失败准备不混入正式样本。
2. 新 Windows 目录缺少当前用户的显式 FullControl，DSH 沙箱在第一条 shell 命令前执行 `SetNamedSecurityInfoW` 失败，模型开始排障。196.220 秒时主动停止该试跑，保存记录，仅为新的隔离工作目录授予当前用户权限并保存原 SDDL，再从空目录开始。沙箱模式维持 `workspace-write`。正式样本中随后发生的 tempfile 故障和排障全部计入 851.714 秒，没有扣除。

原生生成的项目已下载到 `native-work/`。测试代理、DSH、原生 CLI 和本次 SSH 转发均已关闭。逐请求计时与验收数据见[结构化证据](../reference/dsh-agy-latency-rerun-evidence-20261014.json)。
