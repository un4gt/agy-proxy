## 结论

**保留 CLI 原生发包，同时绕开 stream-json 读取原始模型响应，已在单轮文本场景验证可行。**

CLI 自己完成认证、初始化、模型请求和辅助请求；旁路探针观察 `crypto/tls.(*Conn).Write/Read` 的明文，独立解析 HTTP 和 SSE。没有替换上游 URL，也没有让 Python 重新向上游发包。

这只证明原生传输观测的可行性，尚未实现完整代理接入或客户端工具闭环。

## 指纹结论的边界

网络包对照比较了 ClientHello 的 legacy version、密码套件、扩展顺序、SNI、ALPN、支持组、签名算法、支持版本、EC point formats、key share 的组与长度。随机数、会话内容和临时公钥未做逐字节比较。

这些字段的唯一结构集合一致，说明本轮观测没有把 CLI 的 TLS 栈替换成 Python TLS 栈。**不表示所有指纹完全一致**：连接次数已经有波动；GDB 断点会暂停线程，影响时序；未验证所有扩展内容、请求间隔、重试行为和服务端判定。

## 实现中实际遇到的问题

1. Linux 版是可重定位的混合 Go/C++ ELF，不能使用 Windows 探针地址。需要解析 Go pclntab、moduledata 重定位及运行时映射。
2. 辅助接口实际使用 HTTP/2，模型生成在本轮使用 HTTP/1.1；只匹配 POST 请求行会漏流量。探针补充 HTTP/2 帧和 HPACK 解析。
3. Go 栈扩容会重新进入函数。在最初入口观察 Write 会把同一片数据记两次，曾导致一个 HTTP/2 orphan_data。最终将观察点移到栈检查分支之后，重跑未出现该错误。
4. GDB 跟踪退出时会出现进程已消失的寄存器读取错误。最终在 exit_group 入口结束观察并 detach，同时由父进程确认进程消失；不将调试器异常解释为上游调用失败。
