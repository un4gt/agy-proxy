# 工具配置按 AGY 会话加载一次（2026-10-13）

此前代理虽然复用同一个 AGY 进程，却仍在每轮用户消息里追加完整工具声明和桥接规则。这是代理实现中的重复，不是 AGY 要求。原 DSH 耗时测试中，每轮工具配置为 20,883 字符，首个会话 22 轮写入 459,426 字符；原始观测见[耗时分析](dsh-agy-latency-analysis-20261013.md)。

## 修复行为

工具声明、参数 Schema、工具选择、并行约束和固定桥接规则现在在进程启动时写入私有 `.agents/agents/proxy-external.md`，由 AGY 作为 agent 配置加载。同一会话的后续用户输入只携带新增客户端消息，以及适用时的图片指令，不再携带配置块。

“加载一次”指配置不再逐轮追加进对话历史；模型每次推理仍需要使用这份配置，不能据此声称后续推理的配置 token 成本为零。

- `CanonicalRequest.session_instructions` 将配置交给共享执行器；四种客户端协议使用同一路径。
- 会话复用同时比较 agent 配置。工具定义、工具选择或并行约束变化时创建新进程，并加载一次新配置。
- 参数修复重建会话时保留相同配置，重放完整客户端历史并附加候选错误反馈；修复反馈不进入 agent 配置。
- 只允许 `finish` 和现有图片白名单读取，客户端工具仍由客户端执行，交付前完整校验继续有效。

## 回归验证

定向回归 151 项通过；新增测试后的全量回归为 **511 passed、2 skipped**，耗时 62.65 秒。四协议 × 流式／非流式用例检查相同 PID 多轮复用、agent 仅一个配置块、用户历史无配置块、配置变化时重建，以及参数修复时配置和历史保持独立。`git diff --check` 通过。

## 真实 AGY 验证

使用服务器 AGY 1.3.4、`gemini-3.8-flash-high`、`effort=high`，在生产容器内的独立临时目录运行当前源码；数据目录和 AGY 工作目录均隔离，没有替换生产应用或切换流量。打包的 31 个 Python 文件与本地当前源码逐字节一致。

测试沿用此前 DSH 的 25 个工具定义，并增加合成探针。固定 `tool_choice=auto`，通过工具请求、客户端结果回传和后续用户请求连续推进；工具声明始终只放在 agent 配置中。验收脚本位于 `.preview/session-tools-once-20261013/live_incremental.py`。

### 普通多轮往返通过

独立小消息测试在同一 PID / conversation ID 中连续完成 3 次探针调用、3 次结果回传和最终 `CONTRACT_OK` 回答。4 轮均一次生成成功、无修复；agent 文件只有一个工具配置块，4 轮用户消息的工具配置块都是 0。

| 回合 | 验证结果 | 执行耗时 |
| --- | --- | ---: |
| 1 | 使用随机必填字段请求 document-A | 13.770 秒 |
| 2 | 回传结果后请求 document-B | 3.949 秒 |
| 3 | 回传结果后请求 document-C | 2.585 秒 |
| 4 | 最终回答 CONTRACT_OK | 4.066 秒 |

执行耗时合计 24.370 秒，包含首轮 CLI 初始化，不代表 DSH 编码任务耗时。完整脱敏记录（含失败试验）见[结构化证据](../reference/session-tool-configuration-evidence-20261013.json)。

### 第一次逐轮压缩测试

同一 PID 连续 7 轮正确调用探针，第 7 轮输入上下文为 197,105 tokens（未缓存输入与缓存读取相加）。第 8 轮记录到原生 `CHECKPOINT`，耗时 98.327 秒，其中约 79.718 秒后收到 checkpoint 完成事件。8 轮消息的工具配置块合计为 0，无代理修复、无进程重建、无单条输入截断。

压缩后模型请求使用客户端 `read` 读取 AGY 服务器上的 transcript，参数符合客户端 Schema（`file_path`、`limit`、`offset`），但偏离用户指定的探针操作。客户端没有执行这条读取，测试判为失败。这说明“参数契约有效”不等于“模型动作符合任务意图”，不能将本轮描述为压缩后全流程通过。本次修复不包含对这一模型行为的额外改写或自动重试。

### 压缩后续探针未能完成

第二次逐轮测试计划在压缩后调用此前未用过的工具 `probe_lookup_post_c921`，其必填参数仅在会话配置中声明，以验证压缩后仍能读取契约。如果模型先请求客户端读取服务端 transcript，测试客户端会明确返回未执行的错误，再推进探针，且不会修改代理恢复预算。

实际再次在第 8 轮压缩（约 90.488 秒后收到 checkpoint 完成事件），随后模型直接尝试调用 `pwsh`。代理返回 `native_tool_violation` 并回收进程，没有重试，未交付该违规候选。未使用工具的探针因此没有执行，**压缩后的契约保留未完成充分验收**。

检查 AGY checkpoint 可见，长回合只保留开头并标记 `<truncated ... bytes>`，位于末尾的 `document-8` 新指令丢失；记录转而指引读取服务器内部 transcript。该现象不同于下述单条输入进入 CLI 时的截断。两个压缩测试的原始用户输入没有被截断，配置块均未重复，未压缩的前 7 轮都正确完成。

本次保持原生工具限制，不为通过测试开放服务器 shell、文件或 MCP。此压缩兼容问题另行保留，不能将代码回归通过表述成真实压缩验收全部通过。

### 单条超长输入的独立发现

第一次真实测试前两轮工具调用正确。第三轮代理向 CLI 完整发送了 990,546 字符用户输入，其中合成工具结果为 980,064 字符；AGY transcript 的对应 `USER_INPUT` 只有 192,160 字符，并包含 `<truncated 798671 bytes>`。末尾要求调用 `document-C` 的用户指令和 `ARCHIVE_END` 均已缺失，模型返回上一轮的完成说明，验收判定失败，没有触发压缩。

这是本次实测的 AGY 原生单条输入截断，不能当作模型上下文窗口大小，也不是已移除的代理 200,000 字符检查。本次没有为此引入新的代理限制或修改消息。压缩验收改为逐轮回传较小的合成结果，累计历史后检查 AGY 原生压缩。

首次隔离脚本还曾因未打包静态资源目录在导入阶段退出；补齐隔离目录后才开始调用真实模型，该准备错误不计入模型验收。
