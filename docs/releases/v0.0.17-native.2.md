# v0.0.17-native.2 — 原生结果交付前自动恢复

2026-10-20。修复原生后端缺少 `finish` 时将可恢复错误直接暴露给客户端的问题。

## 事件与原因

北京时间 02:42:48，用户 Pi 会话在第 19 次模型请求失败，前 18 次成功。只读核对 CLI conversation：前 18 个模型响应均有一次 `finish`，第 19 个没有函数调用，只有普通文本。线上代码哈希与 `native.1` 匹配，已部署上游 `ANY` 约束；不能把该参数视为模型永远遵守契约的保证。故障时没有保留完整上游请求，不能进一步断言其上游忽略约束的具体原因。

此前原生会话管理器强制关闭恢复，缺失、重复和其他错误共用文案。新实现将无函数调用的已完成响应识别为 `native_finish_missing` 候选错误，通过既有执行器在同一个客户端请求内自动恢复一次。完整恢复后仍须通过原生采集、CLI 确认及客户端 Schema 校验。

## 恢复边界

- 重建原生 CLI/GDB 会话，重放完整客户端历史、原工具契约和校验反馈；不需要用户发送“继续”。
- 所有候选校验恢复共享一次预算和原请求总超时，不无限重试。
- 客户端在校验完成前只接收流式启动／心跳，失败候选不会作为文本或工具调用交付，已执行的客户端工具只作为历史重放。
- 正确累计失败候选和恢复请求的用量；恢复后销毁会话，避免把内部修复提示留入后续对话。
- 修复公共 `SessionManager.restart()` 硬编码常规会话类的问题，重建时保留原生会话类型；不暗中降级为常规 CLI。
- 采集失败、原生／CLI 输出不一致、多次 `finish` 和非法原生工具不会因为本改动被放行。持续失败或超时仍明确报错。
- 增加不含正文的诊断：调用数量、结束原因、上游函数选择模式、会话和轮次。未开启生产正文审计。

故障注入使用临时验证容器补丁：在第一份真实生成结果进入校验器前移除捕获的 `finish`，后续恢复继续调用真实原生 CLI。该补丁不进入发布镜像，也不用于正式服务。首先尝试的工具模式注入未触发缺失错误，日志为一次成功生成；该轮只作为未触发注入记录，不计入自动恢复验收。

四组确定性故障注入（普通回答／工具请求 × 流式／非流式）全部通过，均核对后台 `attempts=2`、`repair_attempts=1`、`usage_complete=true`、`status=SUCCESS`；客户端只收到一份验证后的回答或工具调用。此测试证明恢复链路可用，不代表上游裸文本故障已被消除。
