# v0.0.17-native.8 — 原生 Chat 图片接入

2026-10-27。镜像 `tumuer/agy-proxy:v0.0.17-native.8`，以已发布 native.7 为基底，仅增加图片链路适配。

## 修复的问题

此前原生 Chat 在启动 CLI 前直接拒绝附件，返回 HTTP 400：`Native Chat image support is not yet verified`。仅删除拒绝条件仍会遇到输入清理不接受 view_file、最终捕获不接受读图调用两个阻断点。

本版同时接通三处：附件沿用既有请求专属目录和 PreToolUse 白名单；输入清理仅在收到可信附件清单时保留 view_file，将 AbsolutePath 限制为这些文件；最终校验只允许白名单读取和一个 finish，并确认所有图片读取成功、捕获结果与 CLI 结果一致。输入清理保持开启。非法路径、额外参数、漏读、读取失败及结果不一致不会成为成功响应。

客户端工具仍在客户端执行。Pi 把 read 返回图片放入后续 user/image_url 消息的格式可用；直接放在 role=tool 内的图片块仍不支持。读取和输出均沿用现有图片大小、格式、路径保护与用量规则。

## 验证

本地工作区：`uv run pytest -q --tb=short`，748 passed、2 skipped；跳过项需要 Linux PTY。

实际发布镜像内：`test_native_images.py`、`test_native_input_clean.py`、`test_images.py`，61 passed。测试使用模拟观察器和合成图片，覆盖流式/非流式、像素顺序、成功读取确认、其他会话路径、额外读取参数、遗漏/失败读取、重复 finish、结果不一致及附件清理。

使用实际发布镜像、独立登录状态副本、输入清理开启，对真实 `gemini-3.8-flash-low` 执行 `tests/native_images_smoke.py`：

| 场景 | 结果 | 耗时 |
| --- | --- | ---: |
| 单图，非流式，JSON Schema 输出 | HTTP 200，随机字符与三种图形全部正确 | 18.670 秒 |
| 双图，流式，JSON Schema 输出 | HTTP 200，两组字符、颜色、形状及顺序正确 | 15.944 秒 |
| 同一 CLI 会话续接双图 | HTTP 200，原图片内容正确，复用原会话 | 7.608 秒 |
| Pi 工具历史 + user 图片，普通流式 Chat | HTTP 200，字符与图形正确，正常结束 SSE | 12.272 秒 |

四项均为 attempts=1、repair_attempts=0、usage_complete=true。每轮两次 agent 请求分别用于请求读图和提交结果，不是失败后重放。随机答案没有写入提示，真实请求均未关闭路径限制或输入清理。

上述测试使用 PNG；其他已接受格式有输入校验回归，未在本版逐一对所有模型做真实识图验收。原生序列化/捕获仍有 16 MiB 单次上限，图片编码和历史也占该空间；格式、数量和大小仍受既有图片输入校验限制。

## 部署与回滚

日本节点沿用原 Compose 项目 `agy-proxy`、原目录 `/home/docker_depolyments/agy-proxy`，当前实际生效的文件只有 `docker-compose.yml`。只修改该文件的 image 标签，然后执行：

```sh
docker compose -p agy-proxy -f docker-compose.yml pull agy-proxy
docker compose -p agy-proxy -f docker-compose.yml up -d --no-build agy-proxy
```

镜像先在本地构建并推送仓库，节点确认拉取成功后才重建正式服务；没有在服务器构建镜像或向运行中的正式容器复制源码。

备份目录：`/home/docker_depolyments/agy-proxy/backups/native.8-20261027-images`。包括原 Compose、环境文件及两个数据卷归档。回滚时将 image 恢复为 `tumuer/agy-proxy:v0.0.17-native.7`，执行相同 pull/up 命令；不覆盖现有账号和用量卷。

首次自动核验因 Docker 返回的挂载列表顺序变化而误判，触发一次自动回滚；改为按挂载目标比较后完成更新。部署核验确认环境变量、端口和数据卷一致，原有 1 个账号、4 个 API Key 及用量记录保留，服务 healthy、`/health` 返回 200，原生后端和输入清理均开启。

更新后又通过正式服务的 `127.0.0.1:8317/v1/chat/completions` 验收：双图普通 Chat 返回 200、19.290 秒；Pi 工具历史图片流式请求返回 200、14.242 秒；两者均准确识别新生成的随机字符与图形。随后普通文本精确标记请求也返回 200。该检查使用正式服务和既有 API Key，未输出密钥，也没有修改用户的 Pi 配置。

私有构建清单、差异、真实请求报告及部署核验保存在 `.devdata/native-images-20261027/`；不提交账号、密钥或私有请求正文。
