# v0.0.17-native.4 — 保留原生大输入的完整历史

2026-10-20。修复完整历史或增量工具结果较大时，CLI 按单个输入片段截尾，导致
原生输入清理器报 `Incomplete native capture: hook_error` 的问题。

## 根因与证据

用户会话 `01a15574-9dd3-71a3-8f91-5ed0c13c07c1` 在北京时间 04:17:52 失败，
请求 ID 为 `agy_313b712f0e5a4921aef9827f03c0bce3`。该请求发生在 native.3 切换完成之前：
第一阶段缺少 finish，native.2 已在同一个请求内启动恢复；第二阶段重建会话、重放完整历史时发生钩子错误。
持久化记录为 attempts=2、repair_attempts=1、native_capture_failed、usage_complete=false。

从部署前备份提取的恢复正文为 213,942 UTF-8 字节；CLI 包装后为 214,358 字节。
AGY 1.4.0 的输入序列化器只保留前 192,000 字节，并附上 `<truncated 22358 bytes>`。
客户端历史、恢复反馈及 `</USER_REQUEST>` 尾部均因此丢失。严格清理器拒绝残缺包装，抛出
`Unknown CLI user metadata`，经 input_probe 转换为笼统的 hook_error。

旧容器的详细钩子日志随重建丢失，以上具体原因来自独立容器对备份中原始输入及工具契约的确定性回放。
旧代码回放失败，加入输入保留修复后成功；实际发送到上游的正文与原始恢复正文逐字相等，
SHA-256 为 `c2123eb512dad416b8d61e0228aae394cf20ea6b0018bcdda51936b007221662`。
原始客户正文仅存于私有调试目录，未加入仓库或发布镜像。

事件与确定性回放的详细研究材料仅在本地保留；发布验证结果见下文。

## 修复边界

- 仅在已校验 SHA-256 的原生 CLI 1.4.0、开启输入清理时，启用序列化输入保留钩子。
- 只对代理生成的 `[Complete client conversation]` 和 `[New client messages]` 用户包装，
  将 192,000 字节截尾门槛调整为当前完整片段长度；原 CLI 继续负责分配、序列化和网络发送。
- 在 Go 栈增长检查之后调整参数，避免栈扩张重新进入时重复处理。未改变其他 CLI 截尾、上下文管理或工具权限。
- 保留观察器既有 16 MiB 上界，同时检查用户片段及序列化后的完整输入；JSON 转义、工具定义
  或多个片段使完整输入超限时，同样返回 `native_input_too_large`（HTTP 413），不跳过清理或静默省略历史。
- 不增加恢复次数；先前的单次恢复预算、总超时和交付前完整校验继续生效。
- 输入处理错误现在带独立错误码并写入请求诊断，避免所有失败都只显示 hook_error。
