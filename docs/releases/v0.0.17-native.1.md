# v0.0.17-native.1 — 强制内部 finish 输出契约

2026-10-19。修复原生实验后端多轮工具交互中模型直接返回普通文本、触发 `native_capture_invalid` 的问题。

## 问题与修复

本次用户会话前 7 次模型请求均通过校验，第 8 次在工具结果返回后于北京时间 20:35:48 失败。只读检查 CLI conversation SQLite：前 7 个模型响应各包含一次 `finish`；第 8 个没有函数调用，公开文本为 890 字符。代理拒绝交付该回复。完整会话及正文不进入仓库。

原输入清理仅保留 `finish` 声明，却沿用 CLI 的函数选择模式，模型仍可选择输出普通文本。现在在已验证的 restricted agent 请求上设置 `functionCallingConfig.mode=ANY` 和 `allowedFunctionNames=["finish"]`，让上游解码器遵守内部输出契约，不依赖用户补发“继续”。

`finish` 是桥接封装，普通回答也由它提交；不代表必须调用客户端工具。客户端的 `tool_choice`、工具参数校验、CLI 确认结果一致性校验仍然有效。辅助标题／checkpoint 请求不改写。不把未经验证的裸文本当成成功结果，不增加模型请求重试或重复执行客户端工具。

原生 Dockerfile 从当前源码复制 observer 和 adapter，避免修复被旧正式基础镜像中的 observer 覆盖。新标签 `tumuer/agy-proxy:v0.0.17-native.1`，应用版本仍为 `0.0.17`，AGY 原生二进制仍固定为 `1.4.0`。

## 验证

- Windows 全套回归：584 passed、2 skipped；相关原生与客户端工具回归：77 passed。
- Linux 新镜像内全套回归：586 passed。测试工具 `export_latency.py` 只读挂载用于测试，不进入镜像。
- 新增真实模型验收脚本 `tests/native_finish_smoke.py`：流式／非流式各验证普通回答、`tool_choice=none`、连续 10 次顺序工具请求及结果回填、最终回答；使用随机标记和模拟工具结果，不执行用户工具。
- 日本服务器独立验证实例：上述 26 次真实模型请求全部通过，两组长会话均复用同一 CLI 至第 11 轮。
- Pi 1.1.0 真实客户端：首次完成 read/write/edit/bash，文件结果匹配且无客户端工具或模型错误；客户端重试关闭。
