# v0.0.17-native.3 — 缓存 Token 统计转换修复

2026-10-20。AGY CLI 的输入量和总量不包含缓存读取，而 OpenAI Chat / Responses
及 Gemini 要求包含缓存。之前直接映射导致客户端再次扣减缓存，低估未缓存输入及总量。
Anthropic 的输入量本来就不含缓存，无需改变。内部计数、历史数据库继续保留 CLI 原始口径。

## 事件核对

Pi 会话 `01a15574-9dd3-71a3-8f91-5ed0c13c07c1` 的前 18 个成功请求与服务器备份逐轮吻合。
第 13 轮 CLI 返回未缓存输入 3,152、缓存 14,126、输出 99；旧 API 却返回
`prompt_tokens=3152`、`cached_tokens=14126`。Pi 再扣缓存后将未缓存输入截断为 0。
正确返回值应为 `prompt_tokens=17278`、`total_tokens=17377`。

18 轮合计：输入 235,651（缓存 101,545，未缓存 134,106）、输出 9,505、总量 245,156。
缓存率为 43.1%，旧客户端显示 46.6%。第 19 轮失败时的用量未保存，这些总量不含该次失败的实际消耗。
旧 Pi 会话中的历史统计不会因服务器更新自动重算。

前 12 轮缓存计数为 0，后 6 轮合计命中率 85.1%。历史日志显示会话连续复用；
但没有保留完整上游输入，无法据此证明所有前缀均稳定，也不能确定首次命中是否来自缓存长度门槛。
本次修复的是用量字段语义，并未提高上游缓存命中率，亦不改变 native.2 的 finish 恢复逻辑。

此前测试假数据的缓存量通常为 0，唯一相关单测也误用了不含缓存的总量预期。
这次加入真实故障数字，覆盖四协议 × 流式/非流式，并核对 Pi 扣除缓存后的未缓存量。
验证数字见[脱敏记录](../reference/cache-usage-validation-20261020.json)。
