## 修复

- TLS 连接关闭时清理双向 HTTP 解析器、HPACK、请求关联及未完成的 I/O 观察；同一地址的新 HTTP/2 连接重新初始化，并支持分片前言。
- 修正完整响应缺少 finish、但 CLI structured_output 非 null 时被误判为捕获丢失的分支。
- 交付前的 `native_capture_incomplete` 与候选修复共用一次新进程恢复预算。重放完整客户端历史；失败进程退出池，后续继续不复用失效状态。
- 保留 finish 内容一致性、工具权限与会话隔离校验；捕获失败增加脱敏事件计数，不直接信任 CLI stdout 输出。
- Token 记账复用上游 `usageMetadata` 解析，按请求 ID 替换流式快照后汇总。缓存和思考口径沿用既有协议转换；重试、502、超时及取消保留已知用量，缺失部分标记不完整。

此次事故的 CLI 轨迹已有 finish，但捕获器未关联请求；连接地址复用与分片前言缺陷均已离线复现。
线上原始捕获临时文件已被清理，不能断言地址复用就是此次事故的唯一触发点。
会话证据与捕获器复现的详细研究材料仅在本地保留。
