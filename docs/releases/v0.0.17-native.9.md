# v0.0.17-native.9 — 保留原生上游 HTTP 错误

2026-10-27。镜像：`tumuer/agy-proxy:v0.0.17-native.9`。

摘要：`sha256:c54e2f3ee9ba4e182c7e10901f087bf2ae74c94cc2462047bf0a132c79d3f828`。

## 事故与原因

Pi 在图片工具返回后显示 `Native response has no finish reason`。对应 agy 持久轨迹确认：第一轮已调用图片读取工具，后续生成遇到 HTTP 429；代理错误触发 finish 修复，第二轮直接再次遇到同样的 429。两次真正原因均为 `QUOTA_EXHAUSTED`，不是图片格式错误，也不能据此归因于 ANY 返回纯文本。

上游响应头为 `Content-Type: text/event-stream`，正文却是普通 JSON 错误对象。旧观察器优先依据 Content-Type 读取 `data:` 行，完全跳过错误正文；错误被后续 finish 校验覆盖。

## 行为变化

- HTTP/1.1 和 HTTP/2 均先判断状态码。4xx/5xx 按错误处理，即使正文无法解析也保留 HTTP 状态；可解析时提取明确的配额分类与重置时间。
- 同时识别正常 JSON 或 SSE 数据中的结构化错误。仅处理当前 agent 请求，旁路请求与旧轮次不影响当前结果。
- 明确配额耗尽映射为 `429 / quota_exhausted`；普通 429 映射为 `rate_limit_exceeded`，不错误标记账号额度耗尽。
- 配额耗尽可沿用账号切换机制；没有可用替代账号时保留最初的配额错误和重置时间，不进行 finish 修复。
- 图片读取调用不代表整轮响应结束。CLI stdout 先于网络观察通道到达时，继续读取后续生成的错误或最终 finish。
- 不保存或返回原始错误正文、响应头或被上游回显的请求内容。

非流式请求返回对应 HTTP 状态；客户端 SSE 响应头已经发出时，通过错误事件报告失败，不伪造成功结束。
